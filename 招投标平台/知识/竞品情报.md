## 1. 岚墨 AI

**来源**：[bidmind-ai.com/app](https://bidmind-ai.com/app)

- **标书编写**：招标约束 → 目录 → 素材 → 章节生成 → 导出 Word

**可借鉴**：约束拆成清单、写作必须挂素材、审查按条出报告并能翻回原文。
**处理**：串标比对后置。

## 4. 易标 / OpenBidKit

**来源**：本地开源 `开源项目/tender/OpenBidKit_Yibiao-main/项目总结.md`

Electron + React + SQLite + .NET Open XML；大纲与正文调**用户配置的大模型**，不是写死模板。

**技术方案流水（核心）**

1. 导入招标文件（本地解析或 MinerU）
2. 解析约 18 项；多标段先选范围
3. **5 项必填闸门**：项目概述、技术评分要求、项目信息、甲方信息、交货和服务要求
4. 生成目录（可吃解析结果 + 知识库 + 字数设置快照）→ 人工改标题/增删/排序
5. **提取全局事实**（项目名、工期、地点等）→ 人工确认；改事实会清正文缓存
6. 按**叶子小节并发生成**正文（提示词带解析、事实、知识库摘录、字数目标）
7. 后处理：表格清理、全文一致性、配图（含 Mermaid/HTML 图）、按字数增删
8. 导出 Word；**长任务 checkpoint 可恢复**

**菜单有入口但仍开发中**：商务标、图片知识库、AI 评标、投标机会。

**与我方对照**

| 易标 | 我方 |
|---|---|
| 解析 → 目录 → 正文 → 导出 | 有 |
| 解析项结构化 + 人工必填闸门 | 有「人工校正矩阵」方向；可借鉴 5 项闸门 |
| 全局事实单独抽出并人工确认 | 无单列；可并入矩阵/项目级元数据 |
| 文档知识库勾进提示词 | 有；我方还强调租户隔离 |
| 已有方案扩写 + 覆盖检查 | 贴近喜鹊「以标写标」；未单列 |
| 目录树落 SQLite、任务可续跑 | 有「每步落盘」方向；可直接借鉴实现 |
| 响应矩阵中枢 | 无；易标中枢更像「解析结果 + 目录树 + 全局事实」 |

**可借鉴**：解析分项 + 必填闸门、全局事实、目录字数快照、分节生成与任务恢复、扩写覆盖检查、废标检查与查重入口。

## 跨竞品的共同模式

1. **全部都是投标侧工具**，没有一家做发标开评标交易平台 → 支撑 D10
2. **都在高成本/不可逆步骤前插人工闸门**：确认大纲、确认全局事实、选模板
3. **都强调证据可回溯**：原文页码、来源定位
4. **企业资产倾向分库**：图片库 / 产品库 / 知识库 / 资质库（喜鹊），公司 / 图库 / 技术方案库（ai-tender）
5. **都缺一个「要求落实台账」** → 这正是 D9 的差异化空间
